# 에브리타임 연결 흐름

이 문서는 `$everytime`가 로컬 인증 세션과 백그라운드 HTTP 크롤링을 수행할 때만 읽는다.

## 상태

`READY` → `LOGIN_FORM` → `USER_SUBMITTED` → `SECOND_FACTOR_WAIT` → `AUTHENTICATED` → `SESSION_STORED` → `CRAWLING`

- `READY`: 인증 화면을 준비하기 전
- `LOGIN_FORM`: 사용자가 공식 에타 로그인 화면에서 입력하는 상태
- `USER_SUBMITTED`: 사용자가 아이디·비밀번호를 입력하고 에타에 직접 제출한 뒤
- `SECOND_FACTOR_WAIT`: 에타가 2차 인증 또는 추가 확인을 표시한 상태
- `AUTHENTICATED`: 로그인 후 학교 내부 화면이 확인된 상태
- `SESSION_STORED`: 전용 HTTP 세션의 쿠키를 OS 보호 저장소에 보관한 상태
- `CRAWLING`: 사용자 요청 범위 안에서만 읽기 작업 중인 상태

최초 인증의 실제 실행기는 완료 전까지 사용자 인증을 기다린다. 중간 인증 단계가 확인되지
않았는데 `SECOND_FACTOR_WAIT` 전환을 관측했다고 말하지 않는다.
세션 저장 후 임시 브라우저를 닫고 기본 준비(`everytime.initialize`)를 자동 실행한다.
내 강의·현재 시간표·과목별 최신 강의평을 각각 저장하며, 진행 중에는 `RUNNING`, 전부 준비되면
`READY`, 일부 확인 실패면 `PARTIAL`로 `setup` 캐시에 기록한다.

로그인 입력값, 2차 인증값, 쿠키, 세션 토큰은 상태 데이터에 넣지 않는다. 상태에는 현재
단계와 사용자에게 보여 줄 안내 문장만 둔다. 장기 세션은 OS 보호 저장소에만 암호화해 보관한다.

## 연결 규칙

1. 공식 로그인 화면에서 사용자가 직접 입력한다. 입력값은 AI 대화·로그에 출력하지 않는다.
2. 2차 인증이 필요하면 사용자가 직접 입력하며 연결 프로세스는 인증 완료를 기다린다.
3. 사용자가 2차 인증을 직접 완료하면 연결 프로세스가 `AUTHENTICATED`로 전환한다.
4. 전용 HTTP 세션 쿠키를 OS 보호 저장소에 암호화해 보관하고 `SESSION_STORED`로 전환한다.
5. 새 탭 없이 내 강의·현재 시간표·강의평을 준비하고, 이후에는 세션을 복원해 HTTP로 조회한다.
6. 에타가 브라우저 상호작용을 요구하면 `BROWSER_REQUIRED`를 반환하고 인증 우회를 시도하지 않는다.

최초 연결은 `scripts/connect.py`가 만든 전용 임시 브라우저에서만 수행한다. 사용자가 공식
로그인과 2차 인증을 완료하면 로컬 DevTools의 `Network.getAllCookies` 결과 중
`*.everytime.kr` 쿠키만 OS 보호 저장소로 넘기고 임시 프로필을 제거한다. 브라우저 쿠키 DB를
직접 읽지 않는다.

로그인 유지가 실패하면 세션을 복구하려고 브라우저 쿠키를 추출하지 않는다. 공식 로그인
화면에서 다시 인증하고, 2차 인증이 다시 필요하면 사용자의 직접 입력을 기다린다.

## 기록할 수 있는 결과

```json
{
  "source": "everytime",
  "area": "timetable",
  "title": "자료구조",
  "publishedAt": null,
  "url": "https://...",
  "readOnly": true
}
```

게시판 글·강의 정보·책방 결과는 원문과 URL을 함께 보존할 수 있지만, 비밀번호·인증값·쿠키는
어떤 결과에도 포함하지 않는다.
