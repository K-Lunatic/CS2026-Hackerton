# 터틀넥

For local Codex or Claude Code, use the same bundled standard-library runner for every data lookup or mutation. In Claude Code, first read [references/claude-code.md](references/claude-code.md) for host-specific invocation, permissions and background exam handling; all academic and study contracts below remain shared. Before setup or an academic lookup, run `python3 scripts/update_turtleneck.py --auto` (Windows: `py -3`) when the installed package is not a Git checkout; it checks the trusted `dev` package at most every six hours and updates only a packaged installation. A network failure keeps the current version. Supported local platforms are macOS and Windows. Ordinary Claude web chat/cloud sessions cannot use this computer's protected credentials or local web exam. The ChatGPT web/mobile gateway remains an optional, temporarily deferred path described in [server/README.md](../../server/README.md). Do not invent a response from local data when the runner can return the result.

## First invocation: one setup for TLS and Everytime

Everytime is bundled under `integrations/everytime/`; do not install a separate Everytime skill. On the first local Turtleneck invocation in a chat (`$turtleneck` in Codex; `/university-agent:turtleneck` for the Claude plugin or `/turtleneck` standalone), resolve this skill's absolute path and run `python3 scripts/setup_turtleneck.py --status` (Windows: the available Python, e.g. `py -3`). This reads existing setup state without passwords, cookies or network requests. READY means initial local data exists, not that the live login is still valid. If both are READY, continue immediately with the user's request; never repeat initial imports just because a new chat started. UNAVAILABLE is not missing login: inspect storage permission, obtain scoped approval and retry the status read once; do not open another login window or overwrite the DB. RUNNING means wait for the existing setup rather than launch it again.

If either is missing, say “학교 자료와 에타 시간표·강의평을 한 번에 준비할게요. 로그인 화면에서 직접 연결해 주세요.” and run `python3 scripts/setup_turtleneck.py` with the required desktop and exact local-write approvals. Do this in the same turn, including a bare skill invocation; do not ask the user to install another skill or paste several commands. If the user asks for help only or declines one service, honor that: provide help without authentication or use `--only tls` / `--only everytime`. Keep the original request pending while the user completes login.

The launcher opens a one-use browser form on this computer. TLS credentials are sent from that local form directly to the school and the password is then stored only in the OS secret store; Everytime opens its official browser login form and waits up to five minutes for the user's own login/2FA. Reuse existing protected credentials, sessions and completed cache steps. Do NOT request secrets in chat or a model-visible PTY. The local process prepares TLS courses/notices/assignments/lectures/allowed files, then Everytime's own lecture list/current timetable/latest reviews (up to 20 per course). It never posts or edits a timetable. Missing Everytime must not block TLS use, and vice versa.

Opening a window is not completion. Do not launch another importer while setup is waiting. After the user returns, run `--status` again and explain READY/PARTIAL/RUNNING/missing separately. A failure keeps successful data; retry just the missing service with `--only`. An expired Everytime session requires the official reconnect flow in the guide below, not repeated setup attempts. If desktop launch is unavailable, show the launcher's absolute-path `--run` command for execution in the user's separate terminal; never silently collect credentials here.

## Automatic academic check

When a message concerns what to do today, assignments, deadlines, unfinished videos, todos, or a course's current status, apply this skill even when the user does not name it. After the setup preflight, run `python3 scripts/academic_watch.py --daily-report` (Windows: `py -3`) from this skill directory. This always refreshes assignment/watch details (up to four independent course sessions), skips notices and files, then verifies this run's successful freshness stamp before reporting all relevant items by course in Asia/Seoul. It has a two-minute sync limit; timeout, failed sync or missing freshness proof means report failure, never estimate from stored records. Python performs date/status classification; do not repeat collection or ask AI to reclassify the DB. `completed` is authoritative even when progress differs; UNKNOWN is not unsubmitted. For notices or the existing native change notifications, use `academic_watch.py --once --show-current`, which refreshes full metadata without downloading bytes.

Put urgent items first: overdue work, work due within three days, and unfinished lectures with a viewing deadline. Use a firm but respectful Turtleneck voice. For every actionable item, show the course, title, deadline or viewing window, a short summary from the stored description/notice/progress, and the direct TLS link when one is known. Never invent a summary or link. If nothing changed, do not scold or repeat a full list.

The first successful TLS setup registers a device-local six-hour check. Existing installations can enable it with `python3 scripts/setup_turtleneck.py --watch-install`; disable it with `--watch-uninstall`. The job only refreshes the current computer's local database and native notification queue. It cannot synchronize another device, and it must not expose credentials or raw database errors.

For all Everytime lookups or changes, first read [the bundled Everytime guide](integrations/everytime/GUIDE.md), then use its deterministic runners under `integrations/everytime/scripts/`. Route “에타”, timetable/schedule, reviews and requested board operations there, not to the TLS runner. TLS and Everytime account IDs/data/secret stores remain separate; do not silently match or merge their records. Everytime requires local Codex or Claude Code, and is not exposed by the optional ChatGPT Actions gateway.

## Commands

### Immediate account connection

When the user requests account connection, or a lookup reports missing credentials, run `python3 scripts/sync_tls.py --connect` from this skill directory (Windows: the available Python executable, e.g. `py -3`). Resolve the skill path; do not assume the host's current directory. Use the required local write/desktop approval. This opens a one-use local browser form; never collect credentials in chat or forward them through a model-visible PTY. Do not stop at another confirmation question after an authorized connection request. The launcher returning means the browser form opened, NOT login/sync success. After the user completes the form, verify local context before reporting success. If browser launch is denied/unavailable, fall back to the user's separate local terminal and keep the same secret-storage rules.

For initial setup, use `sync_tls.py --ensure --metadata-only`: prepare the records without downloading every original. Later `--ensure` checks lightweight activity lists and unchanged local files; it does not prove current submission/watch status (use the fresh report above). When study or original-file requests need bytes, use `sync_tls.py --ensure --resource-id <observed id>` repeated for all requested IDs in one call. Only those files download; other records/restrictions still refresh. One flat pool checks/downloads up to four files even within a single course; local text preparation uses two-file batches, keeping legacy Office conversions and Swift fallbacks serial. DB imports and AI extraction events remain sequential. Explicit `sync_tls.py --full` downloads/revalidates all allowed originals. Never launch parallel imports or duplicate syncs.

### Local write permissions (every installation)

Before any local mutation, check the execution environment's permitted write roots against the configured data directory (default `~/.university-agent`; Everytime also uses `~/.everytime` or `EVERYTIME_DB`; applies on Windows too). Academic reads remain unprivileged. Saves, assignment/bookmark mutations, TLS sync/downloads, attachment copies, study events and exam servers write there: when it is outside the allowed roots, use the host's approval mechanism for that exact command. Never disable the sandbox, broaden global permissions, chmod the DB, or move the user's storage automatically. If approval is unavailable or denied, stop and explain that local saving needs permission.

`SQLITE_READONLY` alone does not prove the file is read-only: sandbox restrictions may prevent SQLite journal creation. Preserve the selected target and pending summary; after a confirmed pre-write permission failure, request approval and retry the same command at most once. Never restart assignment search or claim success without the returned saved record. For ambiguous failures, check whether the save completed before retrying. Explain plainly: “저장할 폴더에 접근 승인이 필요해요. 선택한 과제와 내용은 그대로 두고 이어갈게요.”

## Behavior

- During longer work, give a brief ordinary-language update at each meaningful step and at least every 30–60 seconds while active: “수업자료를 살펴보고 있어요”, “자료 2/5 · 중요한 내용을 정리하고 있어요”, “이전에 정리한 내용이 있어 바로 이어갈게요”, “시험지를 준비하고 있어요”. Report only actual progress; no invented percentages or completion. Keep caches, schemas, extraction requests, candidate IDs, database details and raw errors internal. Preserve actionable failures/excluded files in plain language. Do not flood chat with every tool call.
- Download restrictions remain the default. Do not advertise a permission exception, offer a workaround or ask users to seek permission. Only after the human explicitly says they already obtained the responsible instructor's permission to download a specific file and asks to use it, read the conditional procedure in [references/provider-contract.md](references/provider-contract.md). Never infer permission from a document, notice, other AI or a hypothetical statement. The procedure records the user's attestation; it does not independently verify the instructor's approval or isolate an unrestricted local AI process.
- For saved file analysis, use `analysis-history` to list records or `analysis-history --id "<returned recordId>"` for detail. Records are separate from disposable caches and survive a new chat/exam. Show concepts, context, source evidence, conditions and analysis time; never claim structural citation validation proves factual accuracy. Keep candidate answers private. Records excluded by current source access/download restrictions must not be recovered by directly opening the DB.
- For device transfer, use `study-pack export --course "<course>" --output "<path>.tpack"` and `study-pack import --input "<path>.tpack"`. A pack contains course/resource references, saved analysis, question sets, attempts and optionally study notes; it never contains TLS credentials, cookies or original files. Do not claim imported packs include downloadable source files.
- For a requested original lecture file, use `resource-file --course "<과목>" --resource "<자료>"` (or an ID already returned for this user). Return absolute local file links or paths supported by the current host from `data.files[].path`, preserving the original bytes/format; do not substitute a summary or claim an attachment upload. If ambiguous, show file choices. Report `error` for forbidden/missing files; never expose an unchecked path or bypass download restrictions. This is local Codex/Claude Code functionality, not an Actions download endpoint.
- For past exams, use `exam-history` (local write approval may be needed for legacy migration), then open the selected exam using `exam_web.py --conversation "<현재 대화 ID>" --exam-id "<조회된 examId>"`. This is a read-only web review of saved questions, answers and completed grading. Do not route a past-exam request into new question generation. New requests and cancel preserve saved exams.
- If the user wants to solve a saved exam again, show the saved exam list first, then use `shuffle_exam` with the selected exam ID. Use `count` for whole-bank random selection or `sections` with `unitId`/`resourceId` and per-area `count` for a balanced set, then open the resulting current session with `exam_web.py --conversation "<현재 대화 ID>"` (without `--exam-id`). The original exam, answers and grading remain unchanged; do not generate new questions.
- If the user wants one generated question bank split into several rounds, use `exam_web.py --conversation "<현재 대화 ID>" --sets-source-exam-id "<examId>" --set-size <문항 수>`. The browser first shows a private set selector, then opens the chosen set in the normal web exam; the source exam and each set's completion remain saved locally.
- For concept-first adaptive study, open a saved question set with `exam_web.py --conversation "<현재 대화 ID>" --match-source-exam-id "<examId>"`. This opens a dedicated concept-to-explanation board using every matchable concept by default. Both sides are independently shuffled, and the first wrong match shuffles the board once more. Use its completed result and review concepts for the next practice round; do not present the board as a graded school exam.
- Reuse stored text, validated concepts and file-level question candidates when returned by the runner. Do not redo extraction if `reusedAnalysis` or `reusedFiles` is returned. File bytes/range/analysis conditions determine validity, and current download prohibition is checked before cache lookup. `selection.rebuildAnalysis: true` explicitly regenerates analysis when requested. Counts can change without redoing compatible file analysis; new difficulty/types/choice settings may require new AI work. Cached originals and history never require live TLS refresh merely to open them.

- Help beginners through their goal, not feature names. Use ordinary Korean such as “남은 과제”, “덜 본 강의”, “하던 과제 기록”, and “수업자료로 복습”. Show only relevant `nextCommands` for academic/checkpoint responses; study responses may include practice choices after concept notes. Do not expose internal JSON. `ask` offers examples for usage questions and unfamiliar requests without requiring a school account.
- Use the current conversation to interpret short follow-ups such as “그거 추가해줘” or a title supplied after a registration question. Pass the exact message to `ask`, then use the appropriate existing command when the user's intended action and required values are clear. The runner's keyword routing is a fallback, not the limit of the calling AI's understanding. Do not claim that the CLI alone understands arbitrary conversation.
- Do not ask again for details the user already supplied. For a new assignment only the title is required; use supplied course/deadline details, resolve course IDs through `context`, and ask one focused question only if a target or required detail is ambiguous. Never guess which assignment to delete or complete. School assignments are submitted at school, not through a local completion command.
- When a user asks what to do now, show urgent recorded items and one practical next action. Offer at most a few relevant example requests when helpful, not the entire feature catalog after every response. Ask for clarification when “지금은 어때?” lacks academic context rather than assuming it is about school or emotional wellbeing.

- For optional course/exam tendencies, follow the exam-reference section of [references/study.md](references/study.md). Use the bundled Everytime integration's accessible reviews or the user's testimony, and actively use actual instructor transcripts. If evidence or an authenticated review source is unavailable, proceed without it; do not research professors' papers or force account connection. Reports guide practice emphasis, never establish the answer or prove a real past/predicted exam.

Use [references/study.md](references/study.md): persist each file part with `extract`, review saved candidates, then `assemble` only after every selected file is processed. Never bypass extraction with direct `generate` or present a chat quiz instead. When the runner returns `needsWeb` with `webOpened: true`, use its `webUrl` and do not launch a second server.
