# Shared data model draft

이 문서는 팀원이 공통 데이터를 사용할 때 지켜야 하는 1차 계약이다. `database/schema.sql`은 각 채팅 기기에 생성되는 로컬 SQLite DB의 스키마다.

## 기기 로컬 저장

각 기기에 Skill을 설치하면 기본적으로 다음 DB가 생성된다.

```text
~/.university-agent/university.db
```

기기마다 데이터가 분리되며 네트워크 동기화나 공유 폴더를 사용하지 않는다. 다른 경로가 필요하면 `UNIVERSITY_AGENT_DB`를 지정한다. TLS 담당자는 `ingest_tls.py`로 정규화한 TLS 데이터를 현재 기기의 DB에 넣는다.

## 소유권

| 영역 | 데이터 | 담당 |
| --- | --- | --- |
| TLS 동기화 | `users`, `courses`, `enrollments`, `assignments`, `lectures`, `notices`, `resources` | TLS 담당자 |
| 사용자별 학업 상태 | `assignment_submissions`, `lecture_progress` | TLS 담당자 + 기능 담당자 소비 |
| 서비스 기능 | `manual_assignments`, `bookmarks`, `context_bookmarks` | 기능 담당자 |
| 레거시 미사용 테이블 | `projects`, `project_members`, `project_tasks`, `handovers`, `handover_items` | 기존 사용자 데이터를 보존하며 신규 기능에서 사용하지 않음 |
| 조회 조합 | `StudentContext` | 저장하지 않고 조회 시 생성 |

## 핵심 결정

1. 과제와 강의는 여러 사용자가 공유하므로 본체와 사용자별 상태를 분리한다.
2. TLS 외부 ID는 `external_id`에 보존하고 `(source, external_id)`를 유일하게 유지한다. 재동기화는 insert가 아니라 upsert 대상이다.
3. DB 시간은 ISO-8601 UTC 문자열로 저장하고 화면에서 Asia/Seoul로 변환한다.
4. 외부 TLS에 없는 앱 데이터는 TLS 테이블에 섞지 않는다.
5. `StudentContext`는 중복 캐시 테이블로 만들지 않는다. 과제·강의·북마크·프로젝트 조회를 조합한다.
6. 이 DB는 의도적으로 기기별 단일 저장소다. 기기 간 공유와 충돌 해결은 제공하지 않는다.
7. 과제 Context Bookmark는 사용자가 보낸 정형 명령에서만 읽거나 쓴다. 저장은 진행 이력을 append-only로 남긴다. TLS 과제는 동기화에서 `SUBMITTED`/`LATE`가 확인될 때, 직접 등록한 과제는 사용자가 제출 여부에 정확히 `예`라고 답해 완료 처리할 때 해당 이력을 제거한다. 미완성 저장 목록은 정확한 `list` 명령에 응답한다.
   `save "과제명"`은 현재 사용자의 TLS 과제만 검색해 내부 ID에 연결한다. TLS에 없는 캡처 과제는 `save new "제목"`으로 일반 과제 등록과 체크포인트 저장을 함께 한다. 같은 제목의 직접 등록한 과제는 다시 만들지 않고 재사용한다. `load "과제명"`은 저장 기록을 불러온다. 기존 과제 검색에 여러 후보가 있거나 검색 실패 시 체크포인트를 읽거나 쓰지 않는다. 안내·후보·저장/불러오기 결과에는 내부 ID를 내보내지 않는다. 저장 스키마는 그대로 유지한다.
8. 직접 등록한 과제는 `manual_assignments`에 사용자별로 저장하며 TLS 재동기화에서 삭제하지 않는다. 과목과 마감일은 선택 사항이고, 제출 확인에 따른 완료 처리는 TLS 제출 상태를 변경하지 않는다.
9. 조회 컨텍스트의 `asOf`는 한국 시간 조회 시각, `lastSyncedAt`는 사용자 행의 마지막 TLS 가져오기 시각, `dataSource`는 `local`이다. `upcomingAssignments`, `overdueAssignments`, `undatedAssignments`는 미제출 과제를 마감으로 구분하고 `unknownSubmissionAssignments`는 제출 상태 미상 과제를 별도로 반환한다. 새 DB 테이블은 만들지 않는다.
10. `resources.download_status`는 `NOT_DOWNLOADED`, `DOWNLOADED`, `PROHIBITED` 중 하나다. TLS 활동이나 해당 파일을 언급한 공지에서 명시적 다운로드 금지를 확인하면 파일 바이트를 요청하지 않고 `download_reason`을 보존한다. HTTP 403도 서버 거부로 기록한다. 학습 자료 생성은 `PROHIBITED` 파일을 열지 않고 사용자에게 알린다.
11. `assignments.due_at`는 확인되지 않으면 `NULL`이다. 기존 NOT NULL 설치는 다음 쓰기 초기화에서
    같은 트랜잭션으로 테이블을 복사해 전환하며 과제·제출 기록·참조·사용자 인덱스를 보존한다.
12. `permitted_resources`는 사용자+자료별 명시적 교수 허락 진술과 성공적으로 저장한 원본을
    따로 보관한다. TLS 금지 상태를 덮어쓰지 않는다. 현재 수강·주소·제목·금지 사유·교수/학기가
    저장 당시와 같은 경우에만 해당 사용자 조회에서 저장본을 사용할 수 있다. 일반 동기화는
    이 예외를 읽거나 자동 적용하지 않는다. 철회 시 `revoked_at`을 기록하고 파일은 지우지 않는다.
    기존 설치는 다음 쓰기 초기화에서 테이블이 추가되며 읽기 전용 구버전 DB도 조회 가능하다.

## 기능팀이 받는 형태

TLS 담당자는 DB를 직접 노출하지 않고 `TLSProvider`가 아래처럼 사용자별 상태가 합쳐진 레코드를 반환한다.

```json
{
  "id": "assignment-network-5",
  "courseId": "course-network",
  "title": "컴퓨터네트워크 과제 5",
  "dueAt": "2026-10-02T23:59:00+09:00",
  "submissionStatus": "NOT_SUBMITTED",
  "submittedAt": null,
  "source": "tls"
}
```

즉 기능팀은 `assignment_submissions` 조인 방식이나 TLS API를 알 필요가 없다. DB 스키마가 바뀌어도 이 반환 계약을 유지한다.

## 1차 기능 범위

- 과제: 전체, 미제출, 임박한 과제
- 일반 과제: TLS에 없는 과제를 직접 등록해 같은 과제·할 일 조회에 포함
- 강의: 전체, 미시청, 진행률
- 영상 시청 기간: 강의실에 표시된 시작·종료 시각만 `lectures.available_from`, `lectures.available_until`에 저장; 없는 값은 `NULL`
- 할 일: 미제출 과제와 미완료 영상을 과목별로 조합해 조회하며 별도 테이블은 만들지 않음
- 공지: 과목별 최신 공지
- 자료: 과목 PPT/PDF 메타데이터와 기기 로컬 다운로드 경로
- 북마크: 사용자별 대상 북마크
- 과제 컨텍스트 북마크: 사용자별 과제 진행 체크포인트와 복귀 카드
- 프로젝트: 멤버, 업무, 상태
- 학습보조: 읽은 수업자료의 페이지·슬라이드·줄을 근거로 문제 생성과 풀이. 학습 세션은 별도 `study-sessions.db`에 사용자·대화별로 저장한다.
- 학습·시험 메모: `study_context_notes`에 사용자 입력을 과목·시험 종류·차시별로 별도 저장한다. 원문 자료의 근거가 아니라 개념 설명 방식, 문제 유형, 분량과 시간 참고로만 사용한다.

성적, 알림 발송, 벡터 검색, 장기 메모리는 이 스키마에 넣지 않는다.

## 로컬 학습 보관과 재사용

`analysis-records.db`는 캐시와 독립된 자료별 분석 이력이다. `analyses`는 사용자+기록 ID를 기본키로
완료된 파일 분석을 append-only로 저장한다. 재분석은 새 기록이며 캐시 재사용은 새 분석으로 기록하지 않는다.
기록에는 자료/과목 ID·제목·UTC 분석 시각·분석 종류·선택 범위의 본문 해시·출제 조건·원문 위치와 본문,
검증된 개념/맥락/시험 유형/문항 후보가 포함된다. 본문 해시는 전체 원본 파일 해시가 아니라 실제 분석 입력의 해시다.
개념 정리는 읽은 범위에 한정하며 여러 자료에 근거한 개념은 자료별 해당 인용만 저장한다.
현재 접근 가능한 자료만 조회하며 다운로드 금지는 과거 기록 조회에도 적용한다.
`analysis-history`는 읽기 전용 페이지 목록/상세 조회를 제공한다. 상세 조회는 후보 정답을 제외하고
후보 개수와 분석 단위를 제공한다. 원문 인용의 구조 검증과 의미 정확성 미검증 상태를 구별한다.
실패하거나 진행 중인 파일은 완료 기록으로 저장하지 않는다. 모델 이름은 확인 없이 추정해 저장하지 않는다.
새 기록의 `schemaVersion: 2`는 원문을 최상위 `sources`에 한 번만 저장하고 분석 단위의
`sourceRange: [start,end]`로 해당 원문 범위를 참조한다(end는 제외). 기존 1번 형식도 조회 가능하다.
사용자별 시간순·자료별 시간순 인덱스는 다음 기록 저장 시 기존 DB에도 생성한다.
분석 요청 ID와 사용자·자료·종류가 같은 재시도는 같은 기록 ID를 사용한다. 결과가 다르면
덮어쓰지 않고 오류로 알린다. 명시적 재분석은 새 요청 ID로 별도 이력을 남긴다.

`study-sessions.db`의 `study_exams`는 사용자+시험 ID별 문제·당시 답안·채점 상태를 보관한다.
현재 대화 세션을 교체하거나 종료해도 시험은 유지하며 지난 시험 조회는 읽기 전용이다.
시험 조합이 끝난 분석은 `study_pipelines`에 사용자+시험 ID로 별도 보존하고 풀이 세션에는
`analysisRef`만 남긴다. 기존 큰 시험 세션은 다음 쓰기 이벤트에서 같은 트랜잭션으로 분리한다.
`cache/materials.db`는 버전+파일 내용 해시별 위치가 보존된 평문 본문과,
사용자+본문/범위/출제 조건별 검증된 개념·파일별 분석·문항 후보를 보관한다.
다운로드 금지/원본 경로 검사는 캐시 조회 전에 적용한다. 실패·불완전한 분석은 재사용하지 않는다.
파일 경로·크기·수정/변경 시각(ns)·장치/파일 식별자가 같으면 저장한 내용 해시를 재사용한다.
변경된 파일만 스트리밍 해시를 다시 계산한다. 이는 일반 파일 변경 감지이지 악의적인 메타데이터
조작에 대한 무결성 보장은 아니다. 같은 파일·범위·조건의 분석은 본문 조회와 분할 전에 재사용한다.
두 DB 모두 학사 DB 옆에만 저장하며 동기화나 외부 저장소는 추가하지 않는다.
TXT/코드는 UTF-8(BOM 포함), CP949, BOM 있는 UTF-16을 엄격하게 읽고 줄 위치를 보존한다.
깨진 문자로 저장된 이전 텍스트/분석 캐시는 재사용하지 않으며 PDF 등 기존 문서 캐시는 유지한다.
선택적 `examReferences`는 사용자·대화의 시험 준비 정보로만 보관하며 학사 테이블을 변경하지 않는다.
학생 후기는 후보 조합 참고 정보, 실제 교수 전사문은 별도의 첨부 본문으로 분석한다.
긴 전사문은 분석 파이프라인에만 보관해 답안 저장 시 재기록하지 않는다.
`referenceUse`는 출처·교수/학기·적용 이유·최종 문항 ID를 시험 이력에 보존한다.
후기 변경은 자료 분석 캐시를 무효화하지 않는다. 전사문은 내용·출처·위치별로 별도 재사용한다.
`study_context_notes`의 메모는 학사 DB나 분석 원문에 합치지 않는다. `course_id`가 필수이고
`lesson_key`가 있으면 해당 주차·차시 자료를 읽을 때만 적용한다. 손코딩·시험 시간 같은
표현은 보조 태그로 저장하지만 공식 시험 공지나 문제 정답으로 승격하지 않는다.

## ChatGPT 서버 모드

`server/`는 사용자의 컴퓨터에서 실행하며 스키마 변경 없이 TLS 계정마다 별도의 SQLite 파일을 사용합니다. 저장소의 `.university-agent/chatgpt/data/<sha256(TLS 아이디)>.db`에 저장합니다. 별도 호스팅·지속 볼륨이 필요하지 않습니다. ChatGPT 요청의 Bearer 토큰이 사용자를 결정하며, 요청에서 user ID나 DB 경로를 받지 않습니다. 로컬 DB는 자동 업로드하거나 합치지 않습니다. 비밀번호·OAuth 토큰·TLS 쿠키는 학사 DB에 저장하지 않습니다.
