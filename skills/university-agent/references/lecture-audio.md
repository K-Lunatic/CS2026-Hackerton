# 시청 완료 강의 복습

## 현재 구현: 로컬 오디오

- 학교 기록의 `completed=true`만 대상이다. 시청률 100%로 완료를 추정하지 않는다.
- `run_agent.py lecture-audio --course "<과목>"`는 저장된 목록만 조회한다.
- 실제 요청은 `scripts/lecture_audio.py --course "<과목>"`로 실행한다.
  제목 범위는 `--lecture`, 정확한 선택은 반복 `--lecture-id`를 사용한다.
  모든 과목의 완료 강의는 사용자가 전체를 명시했을 때만 `--all-completed`로 요청한다.
  `--check`는 현재 완료·제한·재생 목록만 확인하고 미디어는 받지 않는다.
- 대상 선정은 저장된 강의 목록 기준이다. 방금 본 강의가 빠졌거나 목록이 오래되었으면 먼저
  `sync_tls.py --academic-only`로 현재 학교 기록을 갱신한다. 실제 음원 요청은 선정 후에도
  학교의 완료 상태를 다시 확인하므로 오래된 완료 기록으로 가져오지 않는다.
- 저장된 학교 계정으로 로그인하며 창을 열거나 비밀번호를 모델에 반환하지 않는다.
  연결이 없거나 만료되면 일반 학교 연결 화면으로 복귀한다. 자동 대리 입력은 하지 않는다.
- 현재 수강·활동·공지와 `viewer.php`의 현재 완료 상태를 확인한다. 플레이어 JS는 실행하지
  않으며 진도 전송, 완료 처리, 학습 확인·출석 요청은 절대 호출하지 않는다.
- 별도 허용 표시가 없으면 공식 재생 화면의 실제 음원/영상 주소로 진행한다. 명시적 금지,
  다운로드 거부, 암호화·DRM은 중단한다. 주소·문서 ID·복호화 키를 추측하지 않는다.
- 학교 HTTPS 영상 서버의 실제 포트까지 일치해야 한다. 다른 호스트/포트 리디렉션은 거부한다.
  현재 확인된 경로는 `tls.kku.ac.kr`과 `tlsvod.kku.ac.kr`(영상 서버의 8443 포함)이다.
- 한 번 로그인하고 한 강의씩 처리한다. 재생하지 않는 미디어 조각 읽기만 최대 4개로 제한한다.
  429 응답이면 다음 강의도 진행하지 않는다. 실패한 파일을 자동 반복하지 않는다.
- 확인된 HLS 음성 전용 목록을 우선 사용하고, 없으면 가장 작은 영상 품질의 조각을 받는다.
  현재 지원 범위는 비암호화 MPEG-TS VOD와 직접 MP4/M4A다. 실시간·바이트 범위·fMP4 HLS·
  불연속 조각은 명확한 미지원으로 남긴다. 목록 최대 512KB, 조각 32MB, 직접 파일 256MB,
  전체 임시 영상 1GB다. 한 강의가 실패해도 먼저 저장한 강의는 보존한다.
- 설치된 FFmpeg를 사용하며 없으면 실행 Python에 `requirements-audio.txt`를 의존성 설치
  승인으로 준비한다. macOS 전용 도구를 요구하지 않는다. 외부 URL·쿠키는 변환기에 넘기지 않는다.
- 최종 파일은 학사 DB 옆 `audio/<사용자 해시>/<과목>/<강의>/<출처 해시>/lecture.m4a`에 원자적으로
  저장한다. 임시 영상은 성공·실패 모두 정리한다. `lecture_audio`는 출처 해시·파일 해시·위치·시각만
  저장하며 TLS 진도나 원본 자료 상태를 변경하지 않는다. 원본 주소·쿠키·비밀번호는 저장하지 않는다.
- 저장본을 쓰기 전에 현재 완료·금지·암호화 상태를 다시 확인한다. 원본 목록과 강의 정보가 같고
  저장본 해시가 맞으면 미디어를 다시 받지 않는다. 같은 주소의 내용 변경은 감지하지 못할 수 있다.
- 완료된 음원은 전사문이 아니다. AI가 들었다거나 시험 내용을 확인했다고 주장하지 않는다.

## 다음 단계 설계: 시간표시 전사와 화면 근거 (아직 미구현)

```text
현재 시청 완료 확인 → 로컬 오디오 → 로컬 전사 → 구간별 AI 검수 → 검수 전사문 저장
                                                        │
                                             지칭/수식/도표가 모호한 구간만
                                                        ↓
                                      같은 강의의 해당 시각 화면 → 해당 구간 재검수
```

1. 오디오 내용 해시와 모델·설정 버전으로 처리 여부를 확인한다. 이미 완료한 강의/구간은 재사용한다.
   첫 모델 설치와 첫 전사를 학사 동기화에 넣지 않는다. 중단된 작업은 완료된 구간부터 이어간다.
2. 로컬 음성 인식은 한국어를 지정한다. 음성 활동 탐지로 무음의 허구 자막을 줄이되 원본 시간축을
   보존한다. 파일을 물리적으로 분할하면 각 구간의 원본 시작 시각을 더하고 겹친 문장은 병합한다.
   16kHz mono PCM은 인식용 파생본으로만 만들고 원래 음원을 덮어쓰지 않는다.
3. 전사 저장 단위는 `segmentId`, `startSeconds`, `endSeconds`, `rawText`, 선택적 `words`와
   모델 신뢰 지표다. 시간은 강의 시작 0초 기준이며 ASR 시각은 추정치다. 신뢰 지표를 정확도
   확률로 표시하지 않는다. 원문은 불변이고 검수본 `reviewedText`·근거·수정 이력은 별도로 둔다.
4. 현재 대화의 AI는 2–5분 묶음과 앞뒤 문맥으로 문장·용어·논리 연결을 검수한다. 읽은 강의 자료의
   용어를 참고할 수 있지만 교수 발언에 없던 내용을 추가하지 않는다. 불명확하면 `needsAudio` 또는
   `needsFrame`에 구간 ID·시각·확인할 이유를 반환한다. 먼저 그 주변 음성을 재확인한다.
5. “여기”, “이 식”, “빨간 부분”처럼 화면에 의존하는 표현만 이미지 보충 대상이다. 현재 수강·완료·
   제한을 다시 확인한 뒤 해당 시각 주변 1–3프레임만 가져온다. 재생하거나 시청 기록을 쓰지 않는다.
   HLS `EXTINF`의 누적 시간으로 필요한 조각을 찾고 앞쪽 키프레임 조각부터 받아 로컬 FFmpeg로
   뽑는다. 모든 화면 캡처나 전체 영상 영구 보관은 하지 않는다. 주소는 재조회하고 DB에 넣지 않는다.
   음성용 최저 영상 품질을 그대로 강요하지 않고, 작은 코드·수식이 읽히는 품질의 해당 조각만 고른다.
6. 프레임 근거에는 강의/음원 해시·요청 시각·실제 추출 시각·검수 구간을 연결한다. 말로 들린 내용과
   화면에서 보충한 내용을 구별하고, 화면에서도 해소되지 않으면 `unresolved`로 남긴다.
7. 후속 데이터는 별도 로컬 `lecture-review.db`에 원전사 구간·검수 이력·화면 근거·완료 상태를 둔다.
   AI 검수가 끝나야 `reviewed`이며 강의 전체 완료와 구간 완료를 구별한다. 현재 학사 DB·분석 이력에
   미완료 전사문을 자동으로 합치지 않는다. 이것은 설계이며 해당 DB/전사/이미지 실행기는 아직 없다.

권장 첫 엔진은 [whisper.cpp](https://github.com/ggml-org/whisper.cpp): Mac·Windows 공통 로컬 CLI,
Apple Silicon Metal 가속과 CPU 실행을 지원한다. 한국어에는 `.en` 전용 모델을 사용하지 않는다.
`small` 다국어 모델을 기준으로 실강의 짧은 샘플의 용어 정확도·처리 시간을 재고,
충분한 메모리/가속 환경에서만 `large-v3-turbo`를 비교한다. 작은 모델이 항상 최적이라는 가정은 하지 않는다.

Python 패키지 설치 중심이라면 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)가 대안이다.
CPU INT8, 단어별 시각, VAD를 지원한다. NVIDIA GPU 가속은 추가 런타임이 필요하다.
Apple Silicon 전용 가속을 강화할 경우 [MLX Whisper](https://github.com/ml-explore/mlx-examples/tree/main/whisper)를
별도 대안으로 검토할 수 있지만 첫 구현부터 운영체제별 엔진을 여러 개 유지하지 않는다.

모델은 최초 한 번 다운로드한 뒤 로컬 경로로 고정한다. 이후 음성 인식에서 외부 서비스로 오디오를
전송하지 않는다. 현재 호스트 AI의 검수에는 선택한 전사문·화면이 전달될 수 있으므로
“전사 로컬 처리”와 “모든 처리가 오프라인”을 같은 말로 설명하지 않는다.
긴 강의의 첫 전사는 1–2분을 보장할 수 없다. 처리 시간과 모델 설치 시간을 분리하고,
사용자에게 첫 결과 구간을 먼저 보여주며 나머지를 이어서 처리하는 것이 응답 목표다.
