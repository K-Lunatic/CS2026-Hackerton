# 터틀넥 검증 기록

검증일: 2026-10-02 (Asia/Seoul). 로컬 테스트는 사용자 학사 DB와 분리된 임시 SQLite,
명시적인 자료 fixture와 모의 AI JSON을 사용한다. 테스트 과정에서 사용자 계정 정보를
출력·커밋하지 않았다.

## 자동 검사

### 기능 보존 최적화 (2026-10-02)

0.3.2 릴리스에서는 원격 `d15183e`의 파일별 학습 분석 기능도 통합했으며,
통합 후 로컬 **103개**·게이트웨이 **11개**, 총 **114개** 테스트가 통과했다.

기준 커밋 `99daca6` 대비 과제 조회·검색의 중복 DB 읽기, 날짜·검색어 정규화,
동일한 캐시 강의 페이지의 활동 링크 재파싱을 줄였다. 기존 명령과 응답 형식,
검색 순위와 제출 상태 판정은 유지했다. 조회 결과는 요청 안에서만 재사용하며,
다음 요청은 DB를 다시 읽는다. 활동 링크는 기존 과목 HTML 캐시와 같은 수명으로
재사용하고 과제 상세 페이지는 계속 조회한다.

변경 전 로컬 94개·게이트웨이 11개, 변경 후 로컬 **100개**·게이트웨이 **11개**가
모두 통과했다. 추가 회귀 검사는 필터의 16가지 조합, 같은 마감의 정렬 순서,
반환값 수정 시 원본 보존, 요청별 최신 데이터 반영, 읽기 전용 동작과 HTML 파싱
재사용을 확인한다. HTTP 검사는 로컬 포트 바인딩을 허용한 환경에서 실행했다.

이전 커밋의 Python 모듈을 별도로 로드해 임시 SQLite의 합성 과제 1,201개로
**1,551건**의 반환값·정렬·안내 문구를 대조했고 모두 일치했다. 난수 시드는
`20261002`이며 날짜 경계, 알 수 없는 상태·마감, 수동 과제, 한글·전각 별칭,
500가지 검색 선택자 조합을 포함했다. Moodle fixture의 반환값과 HTTP 요청 순서도
기존 구현과 같았다. 사용자 학사 DB와 실제 학교 계정은 사용하지 않았다.

같은 합성 DB에서 함수별 10회 호출을 5번 반복한 중앙값(호출당 시간)은 다음과 같다.

| 처리 | 변경 전 | 변경 후 | 소요 시간 감소 |
| --- | ---: | ---: | ---: |
| 학사 상태 조회 | 4.210 ms | 2.122 ms | 49.6% |
| 주간 과제 응답 | 10.966 ms | 9.051 ms | 17.5% |
| 이름 검색 | 5.907 ms | 3.741 ms | 36.7% |
| 유사 과제 검색 | 11.430 ms | 7.463 ms | 34.7% |

이 수치는 로컬 합성 데이터 측정이며, CLI 시작 비용이나 실제 TLS 통신 시간,
실계정의 종단간 성능을 포함하지 않는다.

### 이전 검증 기록

로컬 웹 시험 기능 추가 후 전체 로컬 테스트 **89개**가 통과했다. 신규 시험 전용 6개는
유형 확장, 예제 코드·새 유형 정의 검증, 답안 자동 저장·충돌/오래된 시험 거부,
채점 전 정답 비공개, 모든 유형의 AI 평가 대기, 미응답 0점, 잘못된 평가의 원자적 거부,
HTTP 토큰/Origin 보호와 이벤트 파일 기반 채점 재개를 확인한다.
Safari에서 별도 임시 DB 시험지를 열어 객관식·용어 입력, 새로고침 복구, 제출 확인,
수정 잠금, Codex의 기준별 평가 전달과 총점·피드백 표시를 확인했다.
브라우저 검증 문항은 테스트 fixture이며 실제 학교 문제의 출제 품질 검증으로 보지 않는다.
문제 생성의 과목 적합성·정답 의미는 호스트 AI가 검토해야 한다. 실제 Windows 브라우저
동작은 아직 확인하지 않았다. Skill frontmatter는 기본 Ruby YAML 파서로 확인했다.

저장 대화 흐름 수정 후 로컬 **78개**, 게이트웨이 **11개** 테스트가 통과했다.
임시 DB에서 검색 실패 → 검색어 보완 → 후보 선택 → 코드 블록 명령 저장 → 불러오기,
커스텀 제목 저장·재사용, 제출 완료 후보의 사전 안내와 별도 복습 기록을 확인했다.
자연어 검색에 요약이 전달돼도 저장되지 않으며, 여러 명령·추가 문구·빈 제목은 저장되지 않는다.
하이픈이 있는 전체 과제명과 따옴표·코드 블록 형식도 검증했다.
호스트 AI가 대화에서 후속 답변을 해석하는 부분은 Skill 지침이며, CLI 단독의 대화 기억으로
검증한 것은 아니다. 형식 검사 도구는 PyYAML 미설치로 실행되지 않아 frontmatter를 직접 확인했다.

## 실제 학교 자료 범위

기존 학사 DB를 **읽기 전용**으로 먼저 확인했을 때 과목 7개, 자료 메타데이터 53개가
모두 `PROHIBITED`로 기록돼 있었다. 최신 동기화를 격리된 임시 DB에서 실계정으로
실행하다 TLS 자료 페이지의 비표준 마크업이 `NotImplementedError`를 내는 문제를
발견해 수정했다. 수정 후 재실행은 성공했고 과목 7개, 자료 53개가
`DOWNLOADED` 41개와 `PROHIBITED` 12개로 저장됐다. 당시 한 자료에서 107개 구간이 추출됐으나,
이후 문서 뷰어 HTML을 본문으로 잘못 인식한 것으로 확인돼 실제 슬라이드 검증으로 인정하지 않는다.
자료 이름과 본문은 로그에 출력하지 않았고 임시 파일은 검증 후 삭제했다.
이어서 기존 로컬 학사 DB도 정상 동기화해 자료 53개가 `DOWNLOADED` 41개와
`PROHIBITED` 12개로 정리됐다.
수동 과제·과제 체크포인트·북마크·레거시 프로젝트 기록은 동기화 전후 모두 0건으로
건수가 유지됐다. 실제 자료 하나를 선택한 학습 세션은 `prepared`가 됐고,
당시 준비한 107개 구간·30,000자는 위의 뷰어 HTML이므로 출제 근거로 사용할 수 없다.
뷰어 HTML을 제외하는 수정 이후 컴퓨터구조 자료는 `PROHIBITED`로 처리하며,
본문을 확보하지 못한 이유와 직접 자료 첨부 경로를 안내한다.
실제 학교 본문으로 AI가 문제를 생성·채점하는 왕복은 아직 수행하지 않았다.

## 미검증 및 사용 시 제한

- 실제 ChatGPT/Codex 호스트 AI가 `prepared`의 자료로 문제를 생성하고 `grade`에
  의미 평가를 반환하는 대화 왕복은 실행하지 못했다. 코드의 정확 인용 검사는
  답의 의미·오답의 유일성까지 보장하지 않는다.
- ChatGPT 웹·모바일 Actions는 학교 파일 본문 도구가 없다. 사용자가 대화에 직접
  첨부한 텍스트 파일의 실제 GPT 왕복·모바일 동작도 미검증이다. 파일 첨부 지원은
  ChatGPT 제품 기능이며 로컬 학습 세션 검증과는 별개다.
- PDFKit은 이 Mac의 텍스트형 PDF fixture에서 통과했다. Windows의 Poppler 경로는
  모의 실행으로 검증했고 실제 Windows 실행은 확인하지 않았다. 이미지형 PDF OCR,
  손상·암호화 PDF, 실물 모바일·iOS Safari는 확인하지 않았다.
- `skill-creator`의 자동 형식 검사는 실행 환경에 PyYAML이 없어 실행되지 않았다.
  Python 문법·CLI·동작 테스트는 위와 같이 통과했다.
